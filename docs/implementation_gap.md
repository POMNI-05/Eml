## 先纠正两个判断

1. **草稿生成已经默认选中云端。**
   `workspace_panels.py` 的 `Create the draft` 使用 `index=1`，选中
   `Cloud JSON / Gemini`；新客户的 `local_only` 默认也是 `False`。
   这两点已在主页提交之前的代码中存在。尚未完成的是完整的云端优先体验：
   背景文档分析仍依赖 Ollama，GPT 路径仍需要复制请求、取得结构化结果并导入。
2. **自动打码已实现基础层，并非只有用户自定义规则。**
   云端打包会合并内置正则、客户档案、邮件头中的已知姓名/联系人和自定义规则。
   真正不足的是未知实体的覆盖、检测结果展示和逐项核对体验。

代码依据：[生成入口](../workspace_panels.py)、[客户生成设置](../invoice/templates.py)、

## 建议实施顺序

1. **脱敏检查界面与覆盖基线**：复用已有规则，显示自动识别和人工规则的命中、
   来源、替换值；建立已知/未知姓名、邮箱、金额及附件案例，明确应当遮盖和保留的内容。
2. **云端主路径完善**：让用户从选邮件直接走准备、核对、发送、复原；将 Ollama
   配置移到次要入口，并明确背景分析所用路径。保留显式的出站审核。
3. **逐项审核模型**：分开工作状态和审核状态；修改已接受条目后重新待审；最终导出
   检查所含条目，草稿导出继续明确标记为草稿。
4. **专业输出和 PDF**：统一 Word/PDF 的版式及证据编号，并评估长记录分页。
5. **端到端质量验证**：从邮件、打码、草稿、复原到审核导出跑合成案例；分别评估
   隐私遗漏和服务描述准确度。
