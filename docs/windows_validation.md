# Windows 独立版本验证记录

分支：`test/windows-parity`，基于 Mac 交付主线 `54907a9`。
验证环境：Windows、Python 3.14.6、全新项目 `.venv`、Chrome 无头浏览器。
Mac 主线未合并本分支；舍友电脑的实际环境仍需现场验证。

## 已通过

- 从空虚拟环境运行 `Setup.cmd`，安装锁定的直接依赖；`pip check` 无损坏依赖。
- 完整自动化测试 **168 项通过**，涵盖原有 Gmail/附件/脱敏/审核/导出和新增 Windows 隔离、Outlook 适配边界。
- 用真实启动器启动新账号工作区，浏览器显示 OAuth 文件上传页，无页面异常，未访问真实邮箱。
- 用独立合成演示选文件夹和邮件，排除 newsletter，保留所选邮件的附件文字。
- 下载脱敏请求：被排除邮件不在包中，客户名被替换，附件文字保留。
- 点击真实复制按钮并读取浏览器剪贴板：统一系统换行后，与下载请求完全一致。
- 通过浏览器文件上传导入匹配的合成 JSON，执行本地还原，填写审核人、确认并保存。
- 下载真实 DOCX，读取文档内容确认包含审核人及还原的合成客户名。
- 完全停止服务器并重新启动，在 Draft & export 打开已保存草稿，审核人仍在。
- 给测试进程注入指向其它安装的授权/数据库变量，确认这些位置未被访问/创建；演示和真实账号测试使用不同数据库。
- Windows Outlook PowerShell 脚本语法检查通过；适配器模拟测试验证空选择、非邮件、缺 ID、非法 ID 与超时不会返回部分结果。

## 验证边界

这次没有使用真实 Gmail token、没有发送客户邮件到模型、没有发起真实 Gemini 计费请求。
合成演示的返回 JSON 明确是脚本生成，不是模型准确率验证。
Classic Outlook COM 适配尚未在安装 Outlook 的实机上验收；当前使用者选择先验证 Gmail，不依赖 Outlook。

## 舍友电脑上要完成的检查

1. 全部解压 ZIP，确认 Python 3.11+，运行 Setup，然后 Try-Demo。
2. 按 [Windows 操作说明](../START-HERE-WINDOWS.md)完成演示，打开下载的 Word。
3. 若要验证真实账号，启动 Launch-Windows-Test，用允许该账号的 Desktop OAuth 项目授权。
4. 用测试邮件和附件验证 Gmail 搜索/选信，再用获准模型验证复制、返回 JSON 和导出。
5. 关闭重启、检查保存结果，使用测试备份入口保存数据。记录失败步骤，不发送凭证或真实邮件内容作为诊断材料。

Windows 与 Mac 的主要业务流程调用同一套模块。浏览器复制权限、Google 组织策略、Word 渲染及 Outlook 桌面集成
仍会受目标机器影响，因此不把本机测试结果表述为所有设备的完全一致保证。
