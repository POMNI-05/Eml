# 2026-11-17 老板交接：本地启动与接口验收

准备日期：2026-11-15。交付路径是老板电脑上的单用户 Eml，默认采用
“选邮件 → 本地脱敏 → 复制/下载给获准 LLM → 导入 JSON → 人工审核 → Word”。
无需 Ollama 或开发者电脑在线。Gemini API 是可选快捷入口；手动复制不需要 API key。

完整自动化测试：**163 项通过**（Windows，Python 3.14.6）；`pip check` 通过。
测试使用合成数据和模拟接口，不等于老板新账号已经通过真实验收。
Mac 启动脚本保留，但本轮未在 Mac 上实跑。

实际启动检查：Windows `Setup.cmd` 成功；使用空数据目录运行 Launch helper，
Chrome 打开首次登录页，无 Streamlit 异常，无本地模型配置，数据库正常创建。
停止后确认端口关闭、数据库和日志句柄释放。启动检查未登录任何真实账号。

当前邮箱后端是 **Gmail / Google Workspace**。Outlook 只是可选的邮件选择入口，
不提供 Microsoft 365 / Exchange 邮箱后端。如果老板邮箱由微软托管，这份版本不能直接连接该邮箱。

## 安装与现场验收

使用[安装指南](local_install.md)：Windows 首次 `Setup.cmd`、每次 `Launch.cmd`；
Mac 对应 `.command`。公司应持有 Google Desktop OAuth 配置；不要复制开发者的 token 或客户资料。

用虚构客户和测试邮件完成以下操作，确认通过后再使用真实客户内容：

1. 新账号授权，确认 Connected mailbox；新建客户并选择日期、文件夹。
2. 找到 2–3 封已知邮件，包含回复和可提取文字的附件，核对内容。
3. 排除一封邮件，准备脱敏包，核对被排除内容不在包内；必要时补充替换规则。
4. 将审阅后的包交给选定服务，导入返回 JSON，检查引用、还原名称和工作状态。
5. 编辑工作记录、确认审核人、保存并下载 Word，在 Word 打开检查。
6. 关闭再启动，连接同一账号和客户，确认草稿和待处理包仍在。
7. 按安装指南备份，恢复到新目录，再确认草稿存在。记录代码提交号、安装日期及备份位置。

Windows 排查：`.venv\Scripts\python.exe helpers\launch_local.py --check`；
Mac：`.venv/bin/python helpers/launch_local.py --check`。
新安装缺凭证/未启动服务可能产生 warning；健康检查不代表 Gmail 授权有效。
授权过期时重新连接，不需要删除客户数据库。Gemini 失败可改用复制/下载方式。

Google 项目为 **External + Testing** 时，使用 Gmail 范围的 refresh token 通常七天后失效。
同一 Workspace 组织内部使用应由管理员核对 Internal 等适用配置；其它情形按 Google 发布与验证要求处理。
不能仅凭安装成功承诺三个月无需重新登录。[Google OAuth token 说明](https://developers.google.com/identity/protocols/oauth2)

## 三个月不在悉尼：运行方式取舍

| 方式 | 本版本适用性 | 运维要求 |
| --- | --- | --- |
| 老板电脑按需本地启动（本次建议） | 已有启动器，不依赖开发者电脑；关机后再次打开 Launch | 固定版本、公司授权配置、定期私有备份、留一名能按说明排查的联系人 |
| 公司管理的远程桌面电脑/虚拟机 | 可沿用单用户程序；在远程桌面内的浏览器完成授权和操作 | 主机、补丁、备份与远程访问管理；本轮未创建或部署主机 |
| 浏览器访问的正式托管网站 | 需要后续工程，不能只改公网监听地址 | Web OAuth、应用登录、按用户隔离 token/客户数据、持久存储、TLS、备份与监控 |

远程桌面方案在同一远程主机内运行浏览器和应用，符合现有 Desktop OAuth 的本机回调方式。
从老板电脑浏览器直接访问另一台服务器则需要改造授权回调。
[Google Desktop loopback 说明](https://developers.google.com/identity/protocols/oauth2/resources/loopback-migration)

不建议把当前 SQLite 和 token 直接放到 Streamlit Community Cloud 当生产存储；
其本地文件持久性没有保证，本项目也没有多用户隔离。
[Streamlit 数据持久性说明](https://docs.streamlit.io/develop/concepts/connections/connecting-to-data)

## 分支安排

- `main`：默认云包/手动复制路径与本轮交接修复。
- `optional/local-llm`：保留切换前的本地模型版本，已推送；以后可在此继续本地模型实验。
- `codex/client-context-workspace`、`codex/local-cloud-billing`：已合并到 main，随本次交接清理远端分支指针；提交历史保留。
- `feature/emerging`：仍有未合并的 `docs/implementation_gap.md`，保留独有工作。

主线为兼容旧草稿、测试和演示保留本地模型模块，默认 UI 不显示。
维护者显式设置 `EML_ENABLE_LOCAL_LLM=1` 可启用；普通交接不需要该变量。
